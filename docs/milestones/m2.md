# M2 implementation specification: tensors and CUDA runtime/memory

- Status: proposed implementation contract
- Roadmap milestone: M2 in [`docs/plan.md`](../plan.md)
- Prerequisites: completed [M0](m0.md) and [M1](m1.md) contracts
- Immediate consumers: M3 artifact views, M4 reference operators, M5 model execution, and M6 KV pages

This document turns M2 into an executable engineering plan. It fixes the device-neutral tensor and
buffer representation, allocation/accounting rules, CUDA ownership and error boundaries, asynchronous
copy/fence semantics, pooled metadata/workspace lifetimes, validation, tests, and merge order. M2
does not implement a model, general tensor framework, production execution backend, or optimized
kernel library.

## 1. Outcome

At the end of M2, InferX has:

1. a CPU-only `inferx::tensor` library with checked dtype/shape/stride/buffer/tensor views;
2. device-neutral allocator, memory-accounting, fixed-buffer-pool, and completion-fence contracts;
3. an optional `inferx_cuda` implementation that discovers/validates one NVIDIA device and owns its
   streams, events, allocations, pinned staging, metadata ring, and workspace arenas;
4. a strictly asynchronous pinned-host -> device -> CUDA test kernel -> pinned-host path whose only
   normal completion check is an event-backed `CompletionFence`;
5. generation checks preventing stale buffer/event/metadata/workspace handles from releasing newer
   resources;
6. deterministic fake allocator/fence implementations for CPU failure and lifetime tests;
7. category/device/memory-kind current, peak, reserved, and leaked-byte accounting; and
8. retained correctness, sanitizer, stress, and benchmark evidence tied to the exact GPU, driver,
   toolkit, compiler, and build configuration.

The representative data flow is:

```text
validated Shape/Strides/DType
  -> AllocationRequest + MemoryReservation
  -> owning Buffer -> bounded BufferView/TensorView
  -> pinned MetadataLease / WorkspaceLease
  -> cudaMemcpyAsync + explicit stream event dependencies
  -> CUDA byte/strided-copy test kernel
  -> completion event -> CompletionFence::Poll
  -> acknowledge fence -> release ticket resources -> pool slots reusable
```

M2 is complete only on a real supported GPU runner. CPU-only builds remain first-class, but a skipped
GPU job is not M2 evidence.

## 2. Scope boundaries

### 2.1 In scope

- `Device`, `DeviceKind`, `MemoryKind`, `DType`, fixed-rank `Shape`, element `Strides`, byte ranges,
  immutable/mutable tensor views, layout classification, slicing, and permutation.
- Move-only owning `Buffer`, non-owning bounded views, CPU aligned allocator, host reference copy, and
  exact alias/bounds/alignment validation.
- Hardware-neutral allocator request/domain, `MemoryTracker`, reservation transaction, fixed buffer
  pool, strong slot/generation IDs, fake allocator, and failure hooks.
- Hardware-neutral move-only `CompletionFence` backed by a non-owning `FenceDomain`.
- CUDA runtime capability discovery, device guard, health/error translation, nonblocking streams,
  event pool/fence domain, device/pinned allocators, async copy/memset, and debug pointer validation.
- Preallocated pinned/device metadata ring, fixed pinned staging pool, workspace arena pool, and
  resource leases retained through completion acknowledgement.
- One deliberately simple CUDA test kernel for contiguous/strided byte-preserving copy and a bounded
  delay kernel used only by teardown tests.
- M2 configuration/capability validation, device-info diagnostics, unit/integration/correctness/
  stress/failure/performance suites, and required owned-runner CI.

### 2.2 Explicitly out of scope

- Model artifacts/tokenization (M3), mathematical reference operators (M4), model forward (M5),
  physical KV pages (M6), sampling (M7), or serving (M9).
- cuBLASLt, NCCL, CUTLASS, FlashInfer, HPC-Ops, CUDA graphs, NVML, GPUDirect, or managed-memory policy.
- A general tensor framework: no autograd, expression graph, implicit broadcasting, implicit dtype
  conversion, device placement policy, or operator registry.
- `cudaMalloc`/`cudaHostAlloc` in a serving lease cycle. Raw allocators exist for startup, large
  ownership, qualification, and pool construction only.
- `cudaMallocAsync`/CUDA memory pools in M2. Fixed suballocation over startup allocations is the
  baseline; a later ADR may compare stream-ordered pools without changing public lease/fence rules.
- A production `ExecutionBackend`. The M2 harness composes memory/copy/kernel/fence contracts; M4/M5
  add real operator/model submission.
- Cross-process CUDA IPC or peer access. Multiple visible devices are discovered/selected and tested
  independently; distributed ownership begins in M14.
- Host callbacks that call CUDA, default-stream dependence, or hidden synchronization in normal paths.

## 3. Inherited contracts and merge prerequisites

M2 preserves all accepted M0/M1 behavior:

- C++23 host targets, target-scoped warnings, format/tidy/IWYU/header/install gates, offline builds,
  and source/system dependency policy;
- Abseil `Status`/`StatusOr`, strong IDs, checked arithmetic/bytes, monotonic deadlines, and no
  exceptions across module boundaries;
- immutable configuration with provenance and canonical forms;
- coordinator ownership, request epochs, step/ticket identities, plan-buffer leases, and explicit
  completion acknowledgement; and
- CPU simulator determinism. Enabling or building CUDA cannot change M1 replay bytes.

Repository fit at the time of writing is concrete: the worktree has M0's top-level CMake/presets,
`inferx_apply_project_options`, `src/base`, `include/inferx/base`, `apps/inferx_info`, central test
registration, and optional `platform/cuda/smoke`; it has no tensor/runtime implementation yet. M2
extends those conventions with `src/tensor`, `src/runtime`, and `apps/inferx_device_info`, replaces the
smoke only at M2.5, and does not create an unrelated build system. M1 implementation remains a hard
prerequisite even though its specification is already present.

Before M2 merges:

1. ADR 0020 must be accepted with an exact CUDA toolkit/host-compiler/architecture combination;
2. ADR 0006's owned GPU lane must be required for M2 changes and must fail on no device/skipped tests;
3. `docs/supported-platforms.md` must record driver, runtime, toolkit, GPU name/UUID-redaction policy,
   compute capability, memory size, and evidence run;
4. M0's private CUDA smoke is removed only after the M2 integration target covers detection, compile,
   launch, copy, event, and compute-sanitizer behavior; and
5. M1 must be green in CPU presets with `INFERX_ENABLE_CUDA=OFF` and must not load CUDA libraries.

The accepted implementation floor is CUDA 13.0 with the architecture list from ADR 0020. The
qualified combination is CUDA 13.0.88, GCC 13.3, and sm_89. M2 must not use an API newer than the
accepted minimum without a compile/runtime capability guard and supported-platform update.

## 6. Targets, build options, and dependency direction

Always-built/installed targets:

```text
inferx_tensor   -> inferx::tensor   depends on inferx::base
inferx_runtime  -> inferx::runtime  depends on base + tensor
```

CUDA-enabled build-only targets:

```text
inferx_cuda                    STATIC; depends on base + tensor + runtime + CUDA::cudart
inferx_cuda_test_kernels       STATIC/OBJECT CUDA target; test kernels only
inferx-device-info             executable; depends on inferx_cuda
inferx_cuda_integration_test   executable; depends on inferx_cuda + test kernels + GoogleTest
inferx_tensor_cuda_correctness executable; depends on inferx_cuda + test kernels + GoogleTest
inferx_cuda_failure_child      subprocess test executable for context-poisoning cases
inferx_cuda_benchmarks         aggregate build target for four benchmark executables
```

Dependency direction is strict:

```text
base <- tensor <- runtime
base + tensor + runtime <- platform/cuda <- CUDA runtime + test kernels
engine/scheduler may consume runtime/tensor later; tensor/runtime never include engine/scheduler
CPU targets/tests never depend on platform/cuda or CUDAToolkit
```

`inferx::tensor` and `inferx::runtime` are installed static targets and added to the independent
consumer/header tests. `inferx_cuda` is not installed in M2; it is an internal platform implementation
until M4 defines a stable backend composition surface.

M2 preserves the existing CUDA switch and adds the remaining scoped options:

| Option | Default | Rule |
|---|---:|---|
| `INFERX_ENABLE_CUDA` | inherited `OFF` | When `ON`, enable CUDA and require accepted toolkit/arch/device tests |
| `INFERX_BUILD_GPU_TESTS` | `ON` top-level with CUDA | Cannot be `ON` without CUDA; owned CI requires it |
| `INFERX_BUILD_COMPUTE_SANITIZER_TESTS` | `OFF` locally, `ON` GPU CI | Requires `compute-sanitizer`; absence is CI failure |
| `INFERX_CUDA_ENABLE_LINEINFO` | `ON` for GPU test preset | Adds line info to InferX kernels without debug (`-G`) performance distortion |

Use `find_package(CUDAToolkit 13.0 REQUIRED)` only inside the enabled CUDA branch, link shared
`CUDA::cudart`, and keep `CMAKE_CUDA_RUNTIME_LIBRARY=Shared`. Do not link the driver API, cuBLAS,
NCCL, CUTLASS, FlashInfer, or NVML in M2. CUDA is a qualified system dependency, so no new source
submodule/profile is added. Abseil, GoogleTest/GoogleMock, and Google Benchmark remain at M0 pins.

The CUDA target uses the accepted explicit `CMAKE_CUDA_ARCHITECTURES`; `native`, all-major/all, PTX-only
release artifacts, and silently dropping an unsupported architecture are forbidden. NVCC uses C++23
only if ADR 0020's selected toolkit proves it; otherwise `.cu` files are isolated at C++20 while all
host-facing headers remain C++23-compatible.

## 7. Device-neutral tensor contract

### 7.1 Device, memory kind, and dtype

```cpp
enum class DeviceKind : uint8_t { kHost = 0, kCuda = 1 };
enum class MemoryKind : uint8_t {
  kHost = 0,
  kPinnedHost = 1,
  kDevice = 2,
  kManaged = 3,
};

struct Device {
  DeviceKind kind;
  DeviceId ordinal;
  absl::Status Validate() const;
};

enum class DType : uint8_t {
  kBool,
  kUInt8,
  kInt8,
  kUInt16,
  kInt16,
  kUInt32,
  kInt32,
  kUInt64,
  kInt64,
  kFloat16,
  kBFloat16,
  kFloat32,
  kFloat64,
};
```

Host device ordinal must be explicitly constructed as zero. `kHost` memory is valid only on host;
`kPinnedHost` is host-addressable and associated with the CUDA device/domain that registered it;
`kDevice` is not host-addressable. `kManaged` is reserved in the type vocabulary but allocation,
host spans, and copies involving it return `Unimplemented` in M2.

Pinned buffers report `Device{kHost, DeviceId(0)}` because their address space is host; their private
allocation domain records the CUDA registration/owning device. Memory accounting therefore applies
the configured pinned limit process-wide rather than pretending pinned bytes are device memory.

`DTypeSize`, `DTypeName`, `IsFloatingPoint`, and `IsIntegral` are total checked switches. FP16/BF16
are storage types in M2; generic headers do not include CUDA half types or define arithmetic. Bool is
one byte. Quantized packings/scales are layout descriptors added in M13, not hidden fractional dtype
sizes.

### 7.2 Shape and strides

`Shape` and `Strides` use inline `std::array<uint64_t, 8>` storage and an 8-bit rank, so construction,
copy, comparison, and common transformations allocate nothing. Public construction goes through
checked factories:

```cpp
class Shape {
 public:
  static absl::StatusOr<Shape> Create(std::span<const uint64_t> dimensions);
  uint8_t rank() const;
  uint64_t dim(size_t axis) const;
  std::span<const uint64_t> dimensions() const;
  absl::StatusOr<uint64_t> NumElements() const;
  absl::StatusOr<ByteCount> Bytes(DType dtype) const;
};

class Strides {
 public:
  static absl::StatusOr<Strides> CreateElements(
      std::span<const uint64_t> element_strides);
  static absl::StatusOr<Strides> Contiguous(const Shape& shape);
  uint64_t elements(size_t axis) const;
};
```

Rank zero is a scalar with one element. Any zero dimension makes an empty tensor with zero elements/
bytes. Rank above eight is `InvalidArgument`; products/sums that exceed `uint64_t` or `ByteCount` are
`OutOfRange`. Strides are in elements, never bytes; negative strides and implicit broadcast stride
zero are unsupported. A stride of zero is accepted only for an axis whose dimension is zero or one.

`LayoutAnalysis` computes, with checked arithmetic:

- contiguous row-major status (dimension-zero tensors are contiguous);
- maximum reachable element/byte offset;
- non-overlap by sorting axes with dimension > 1 by stride and requiring each stride to be at least
  the accumulated lower-axis span; and
- dense-versus-padded status.

Immutable views may be overlapping but are marked `kMayOverlap`; mutable views require non-overlap.
M2 does not guess injectivity beyond this documented analysis.

### 7.3 Byte ranges, buffers, and views

```cpp
struct ByteRange {
  ByteCount offset;
  ByteCount size;
  absl::Status ValidateWithin(ByteCount allocation_size) const;
};

struct AllocationRequest {
  Device device;
  MemoryKind memory_kind;
  ByteCount bytes;
  ByteCount alignment;
  MemoryCategory category;
};

class Allocator {
 public:
  virtual ~Allocator() = default;
  virtual absl::StatusOr<Buffer> Allocate(const AllocationRequest& request) = 0;
};
```

`Buffer` uniquely owns one allocation and is move-only. It stores address, size, guaranteed power-of-
two alignment, device/memory/category, an allocation ID, and a `shared_ptr<AllocationDomain>` whose
shared lifetime is the deliberately documented exception to unique allocation ownership. The domain
owns deallocation/error-reporting capability, not the allocation; it may outlive the allocator facade.

`Buffer::Release()` is explicit and returns deallocation status. The destructor is `noexcept` and
calls the domain's no-throw fallback only for an unreleased buffer. CPU fallback frees; CUDA fallback
does not call potentially synchronizing `cudaFree`/`cudaFreeHost`: it records leaked bytes, poisons the
domain, and leaves process teardown to reclaim them. Normal CUDA shutdown releases buffers explicitly
after fences. Move leaves a canonical empty buffer. Zero-byte buffers have null address but retain
device/kind/category and require no deleter call.

`BufferView`/`MutableBufferView` contain a non-owning raw address privately plus validated byte range
and metadata. Creation is only through `Buffer::View`/`MutableView`; subviews use checked offset+size.
The view does not extend allocation lifetime and remains valid across a `Buffer` move but not release/
destruction. Hardware-independent callers see address only through checked host byte spans, which are
available for host/pinned memory and rejected for device/managed memory. A private tensor access shim
used by `platform/cuda` obtains the raw address; it is not installed as public API.

Subview alignment is the greatest guaranteed power-of-two divisor common to base alignment and
offset (offset zero retains base alignment). Requests require nonzero power-of-two alignment and
checked narrowing to `size_t`. Pointer values are never serialized, logged as identity, hashed, or
used to compare allocations.

### 7.4 Tensor views and transformations

```cpp
class TensorView {
 public:
  static absl::StatusOr<TensorView> Create(
      BufferView buffer, DType dtype, Shape shape, Strides strides,
      ByteCount byte_offset = ByteCount(0));
  absl::StatusOr<TensorView> Slice(
      size_t axis, uint64_t begin, uint64_t end, uint64_t step = 1) const;
  absl::StatusOr<TensorView> Permute(std::span<const uint8_t> axes) const;
};

class MutableTensorView {
 public:
  static absl::StatusOr<MutableTensorView> Create(
      MutableBufferView buffer, DType dtype, Shape shape, Strides strides,
      ByteCount byte_offset = ByteCount(0));
  TensorView AsConst() const;
};
```

Creation checks rank equality, dtype alignment, base offset, reachable last byte, and overflow before
storing a view. Empty tensors may end exactly at the buffer boundary and never dereference. Mutable
creation rejects overlap. Slice uses half-open indices and positive step; permutation must contain
each axis exactly once. Neither operation copies data or allocates. M2 has no reshape unless input is
contiguous and element count matches exactly.

`TensorView` is immutable by type. CUDA/CPU write functions require `MutableTensorView`; casting away
const or constructing a mutable view from an immutable one is impossible through supported APIs.

### 7.5 CPU allocator and reference copy

`CpuAllocator` uses aligned C++ allocation, checks `ByteCount -> size_t`, reserves accounting before
allocation, and translates `std::bad_alloc` to `ResourceExhausted`. It supports host memory only and
zero-initializes only when explicitly requested by a separate fill operation.

`CopyTensorCpu(source, destination)` requires equal shape/dtype, host-addressable memory, and valid
non-overlapping destination. It walks logical row-major indices against each view's element strides;
contiguous equal-size views use `std::memmove`. Other source/destination byte-range overlap is rejected
because traversal could overwrite unread elements. The strided path is the independent correctness
oracle for the M2 CUDA kernel. It performs no dtype conversion.

## 8. Memory accounting, pools, and fake implementations

### 8.1 Categories and tracker

```cpp
enum class MemoryCategory : uint8_t {
  kModelWeights, kKvCache, kWorkspace, kExecutionMetadata,
  kPinnedStaging, kRuntimeInternal, kTest,
};

struct MemoryKey { Device device; MemoryKind kind; MemoryCategory category; };
struct MemoryCounters {
  ByteCount limit;
  ByteCount reserved;
  ByteCount committed;
  ByteCount peak_committed;
  ByteCount leaked;
  uint64_t live_allocations;
};
```

`MemoryTracker` has immutable limits per `(device, kind)` and stable category splits. It is
thread-safe because startup paths may allocate concurrently, but it is not on a pool lease hot path.
`BeginReservation(key, bytes)` checks limits and returns a move-only transaction. Allocation success
commits an `AllocationCharge` into `Buffer`; failure/destruction rolls it back. Successful free drops
committed bytes. Failed CUDA free moves bytes to `leaked`, retains the live allocation diagnostic, and
poisons the domain rather than pretending capacity returned. Snapshots use stable key order and no
request/pointer labels. Destruction requires baseline counters or an explicit poisoned-device leak.

### 8.2 Fixed buffer pool

`FixedBufferPool::Create(Buffer backing, PoolGeometry)` divides one allocation into checked, aligned,
equal-size slots. Acquire uses deterministic lowest-slot order, increments generation, and returns a
move-only `BufferLease`; no freelist node is allocated after creation.

```cpp
struct PoolToken { PoolSlotId slot; PoolGeneration generation; };
class BufferLease {
 public:
  BufferLease(BufferLease&&) noexcept;
  ~BufferLease() noexcept;
  BufferView view() const;
  absl::StatusOr<MutableBufferView> mutable_view();
  PoolToken token() const;
  absl::Status Release();
};
```

Full pool is `ResourceExhausted/kPoolExhausted`. Generation wrap retires the slot. Duplicate, foreign,
or stale release is `FailedPrecondition/kStalePoolLease` and cannot free a newer owner. The normal
pool is coordinator/device-worker owned without a mutex; a mutex adapter exists only for MPMC tests.
Pool destruction requires all leases returned.

### 8.3 Fake implementations

`FakeAllocator` owns bounded host storage, honors metadata without exposing fake device memory as
host-accessible, and injects failure by allocation ordinal/category/threshold. `FakeFenceDomain`
supports manual pending/complete/fail and arbitrary starting generations. They drive CPU pool/fence/
failure tests; CUDA semantics still require GPU tests. Test doubles are not installed.

## 9. CUDA device, API, and error boundary

### 9.1 Capability discovery

`DiscoverCudaDevices()` returns value-only `CudaDeviceInfo`: ordinal, sanitized name, compute
capability, total memory, SM/warp/thread limits, copy-engine count, UVA, host mapping, managed-memory,
stream-priority, memory-pool support, and driver/runtime versions. UUID is local diagnostics only and
redacted from goldens.

Discovery distinguishes missing/insufficient driver, no device, invalid device, and unsupported SM.
`ValidateCudaCapabilities` checks the accepted matrix, UVA, configured budgets plus reserve, `size_t`
narrowing, and pool geometry before context creation. M2 selects one device; multi-device systems run
the isolated suite per ordinal without peer access.

### 9.2 Runtime seam and health

`CudaApi` is an immutable table of typed function pointers for only M2 cudart calls. Production points
directly to cudart; a CUDA-test table counts allocation/free/sync/copy/event/stream/launch calls and
injects synchronous failures. It is passed explicitly and never globally replaced. No CUDA function
is called from a host callback; normal code never uses the default stream.

Append explicit `ErrorReason` values: `kCudaInvalidDevice=100`, `kCudaOutOfMemory=101`,
`kCudaLaunchRejected=102`, `kCudaAsyncFault=103`, `kCudaDeviceLost=104`, `kCudaApiFailure=105`,
`kStaleFence=106`, `kStalePoolLease=107`, `kPoolExhausted=108`, `kPendingResource=109`, and
`kUnsupportedCapability=110`. M1 values are not renumbered; new reasons require the M2 diagnostic
schema.

| CUDA result | Abseil code | Scope/action |
|---|---|---|
| invalid user argument/device before submission | `InvalidArgument`/`NotFound` | Reject operation; context remains healthy |
| invalid CUDA resource handle after wrapper validation | `Internal` | Ownership invariant failure; poison context |
| allocation failure | `ResourceExhausted` | Fail allocation/step; tracker unchanged |
| unsupported capability | `Unimplemented` | Fail startup/readiness |
| invalid launch configuration/out of resources immediately | `InvalidArgument`/`ResourceExhausted` | Fail step before fence |
| `cudaErrorNotReady` from query | `FenceState::kPending` | Not an error |
| illegal address, timeout/failure, assert, device lost, sticky async error | `Unavailable` | Poison context; reject work; terminate worker after drain |
| stale slot/generation | `FailedPrecondition` | Do not touch newer resource |

Status payloads carry stable operation, CUDA numeric code/name, device, fault scope, and retryability.
`cudaPeekAtLastError` checks each launch without clearing unrelated state. Queries can surface earlier
async errors and always pass the health classifier. `CudaHealth` is `kHealthy`, `kPoisoned`,
`kShuttingDown`, or `kClosed`; first poison cause wins. No work begins unless healthy.

`CudaDeviceGuard::Create` records current device and switches only when needed. `Restore()` is
explicit/idempotent; destructor best-effort restores and records failure without throwing. The worker
pins its device at startup and does not construct a guard per operation.

## 10. Streams, events, and completion fences

### 10.1 Streams and event pool

`CudaStream::Create` validates device/role/priority and creates `cudaStreamNonBlocking`. M2 roles are
compute and optional transfer. Actual clamped priority is recorded. Record/wait/query/copy adapters
validate same-device ownership. `Close()` reports destroy errors; fallback destruction never calls a
stream/device synchronize.

`CudaEventPool::Create` pre-creates `event_pool_slots` events with `cudaEventDisableTiming`; a small
separate benchmark pool enables timing. Acquire returns a one-record-only move-only event lease with
slot/generation. Unrecorded polling is a contract error even though raw CUDA reports success. Not-ready
events are never reused. Stale access cannot query/release a newer generation; wrap retires the slot.

### 10.2 Hardware-neutral fence

```cpp
enum class FenceState : uint8_t { kPending, kComplete, kFailed };
struct FenceToken { Device device; FenceSlotId slot; FenceGeneration generation; };
struct FencePoll { FenceState state; absl::Status completion_status; };

class FenceDomain {
 public:
  virtual ~FenceDomain() = default;
  virtual absl::StatusOr<FencePoll> Poll(FenceToken) = 0;
  virtual absl::Status WaitUntil(FenceToken, Deadline, FenceWaitReason) = 0;
  virtual absl::Status Acknowledge(FenceToken) = 0;
  virtual void Abandon(FenceToken) noexcept = 0;
};

class CompletionFence {
 public:
  CompletionFence(CompletionFence&&) noexcept;
  ~CompletionFence() noexcept;
  absl::StatusOr<FencePoll> Poll();
  absl::Status WaitUntil(Deadline, FenceWaitReason);
  absl::Status Acknowledge();
};
```

The fence has a non-owning domain pointer; context/domain outlive it. Poll maps not-ready to pending
and sticky errors to failed/poisoned. Acknowledge is exactly once after complete/failed observation
and returns the event. Destruction of a live fence calls `Abandon`, transferring it to deferred
reclaim without waiting; pending events never become immediately reusable.

The fence owns only completion/event state, not buffers. Any ticket/submission that associates memory
with it must retain that resource bundle until acknowledgement; abandoning such a ticket transfers
fence and bundle together to its context. Destroying a standalone fence never authorizes a caller to
free separately owned memory.

Wait is allowed only for named test/startup/diagnostic/shutdown reasons. It queries with bounded 50 us
to 1 ms backoff to honor deadline; normal execution never waits. Raw event/stream/device synchronize
calls are confined to named helpers and counted by `CudaApi`.

## 11. CUDA allocation and copies

`CudaDeviceAllocator` uses `cudaMalloc`; `CudaPinnedAllocator` uses `cudaHostAlloc` during context/pool
construction or explicit large ownership. Both reserve accounting first and attach a shared domain.
Pinned bytes have a separate budget. Managed allocation and arbitrary host registration are
`Unimplemented`.

Explicit release requires all consumer fences complete. Device release uses `cudaFree`; because that
may synchronize for ordinary allocations, shutdown first proves no outstanding work. Pinned release
uses `cudaFreeHost` after copy fences. Neither appears in pool lease/release.

```cpp
struct CopyRequest { BufferView source; MutableBufferView destination; ByteCount bytes; };
absl::Status CopyAsync(const CopyRequest&, CudaStream&);
absl::Status MemsetAsync(MutableBufferView, uint8_t value, CudaStream&);
```

Copy validates ranges, devices, debug pointer attributes, and direction. Normal H2D/D2H requires
pinned host memory; pageable async returns `FailedPrecondition` because CUDA may synchronize/stage it.
The pageable benchmark uses a clearly named raw benchmark adapter. D2D is same-device; H2H is CPU.
Zero bytes makes no CUDA call and overlap is rejected. Success means queued, not completed; caller
records a fence after the final operation before reading/releasing memory.

## 12. Metadata, staging, and workspace lifetime

`CudaMetadataRing::Create` allocates paired pinned/device slots. States are free, host-writable,
uploaded, and in-flight, each generation checked:

```text
Acquire -> fill pinned view
-> SealAndUpload(transfer, compute): async H2D, record upload event, compute waits event
-> immutable device view; move lease into consumer resources
-> record consumer fence on compute
-> acknowledge fence, then release metadata lease -> free
```

The upload event stays owned until the consumer fence. Writes after sealing, second upload, early/
stale release, and cross-device streams fail without mutation. No host wait occurs.

A `FixedBufferPool` over pinned backing provides staging slots; oversize requests fail and never fall
back to pageable memory. `WorkspaceArenaPool` splits fixed device backing into arenas.
`WorkspaceLease::Allocate(bytes, alignment, tag)` is checked bump allocation; failure leaves offset
unchanged, slices do not individually free, and the lease stays with submission resources through
fence acknowledgement. Geometry is immutable and high-water usage uses a closed tag enum.

## 13. Device context and shutdown

`CudaDeviceContext::Create(config, tracker, api)` validates and allocates transactionally. Member
declaration/destruction order is: API/domain/health/info; allocators/tracker; streams; event domain;
staging/metadata/workspace; deferred fences/submissions. Creation failure closes the constructed
prefix in reverse and returns first error plus cleanup diagnostics.

The context is worker-thread-owned. Shutdown is explicit/idempotent:

```text
Healthy -> ShuttingDown; reject acquire/submission
-> poll/ack live and abandoned fences until deadline
-> deadline: return DeadlineExceeded while retaining all resources for retry
-> one named shutdown device sync checks sticky status
-> explicitly free backing buffers
-> close events, streams, allocation domains
-> tracker baseline -> Closed
```

Destructor requires `Closed` and never hides a blocking sync. Poisoned contexts follow memory-safe
drain, then the worker exits; illegal-address/device-lost cases run as subprocess tests.

## 14. Integration harness

Test-only `CudaTestPipeline` acquires pinned input/output, device buffers, metadata, and workspace;
enqueues H2D on transfer; records the upload event; makes compute wait; launches a strided byte-copy
kernel; records a compute-done event; makes transfer wait; enqueues D2H on transfer; records the final
completion fence on transfer; and returns immediately. The caller polls that final fence, validates,
acknowledges, then releases all resources. Thus completion covers both kernel and host output, with no
host synchronization hidden between streams.

The return type is move-only `CudaTestSubmission`, which owns the fence and every input/device/
metadata/workspace/output lease. It exposes `Poll()` but not output bytes while pending.
`FinishCompleted()` requires a completed poll, acknowledges the fence, releases device/temporary
resources, and returns the pinned output lease for validation. Destruction while pending abandons the
fence and transfers the whole resource bundle to context deferred reclamation; it never frees views.

The kernel accepts ranks 0..8 and M2 element sizes, performs no conversion, and uses explicit grid/
block plus immediate launch check. A bounded-delay kernel is compiled only into teardown tests.
A small correct shared-memory/barrier probe is test-only input for racecheck/synccheck; it is not an
operator or performance primitive.

## 15. Configuration and diagnostics

M2 adds a versioned `cuda` section to the immutable configuration. M1 schema-v1 files remain valid
with CUDA disabled; M1 simulator/replay continues using its v1 canonical form. A config that contains
M2 fields canonicalizes as engine schema v2.

| Field | Range | Default | Rule |
|---|---|---:|---|
| `cuda.enabled` | bool | false | True requires CUDA build/capability |
| `cuda.device_id` | nonnegative device ordinal | 0 | Must exist and pass supported matrix |
| `cuda.device_reserve_bytes` | 0..device total | 512 MiB | Never included in allocatable budget |
| `cuda.device_budget_bytes` | null or positive | null | Null = total minus reserve; explicit must fit |
| `cuda.pinned_budget_bytes` | 1 MiB..4 GiB | 256 MiB | Process-wide pinned limit |
| `cuda.event_pool_slots` | 8..65,536 | 1,024 | Must cover in-flight/upload/deferred fences |
| `cuda.timing_event_slots` | 2..256 | 32 | Benchmark/diagnostics only |
| `cuda.metadata_ring_slots` | 2..64 | 3 | Paired pinned/device slots |
| `cuda.metadata_slot_bytes` | 4 KiB..16 MiB | 1 MiB | Power of two |
| `cuda.staging_pool_slots` | even 2..256 | 4 | Fixed pinned input/output slots |
| `cuda.staging_slot_bytes` | 4 KiB..64 MiB | 4 MiB | Power of two |
| `cuda.workspace_slots` | 1..64 | 4 | At least configured max in-flight steps |
| `cuda.workspace_bytes_per_slot` | 1 MiB..4 GiB | 16 MiB | Checked total allocation |
| `cuda.enable_transfer_stream` | bool | true | False aliases copy work to compute explicitly |

MiB/GiB mean powers of 1,024; JSON stores integer bytes. Validation sums all startup allocations and
tracker reserves with checked arithmetic, requires event capacity for metadata uploads plus completion
fences, and rejects geometry exceeding budget before calling CUDA. Environment/CLI names follow M1.

Let `max_test_inflight = min(metadata_ring_slots, workspace_slots,
staging_pool_slots / 2)` because the harness needs input and output staging. Validation requires
`event_pool_slots >= metadata_ring_slots + 2 * max_test_inflight`: one retained upload event per
metadata slot plus compute-done and final-completion events per in-flight pipeline. All arithmetic is
checked; later execution backends supply their own stronger event-capacity formula.

`inferx-device-info --json` prints stable schema version, toolkit/driver/runtime, selected device
capabilities, accepted/actual SM, configured/resolved budgets, pool geometry, and health. Human mode
may show device name; canonical JSON omits UUID, PCI bus address, pointers, hostname, and wall time.
`--self-test` runs the integration path and returns nonzero on a skipped/unsupported device.

## 16. Invariants and error containment

Check after every debug/test acquire, submission, poll, acknowledgement, and shutdown phase:

- every live buffer has exactly one allocation charge; tracker totals equal live allocation records;
- every pool slot is free, leased, retired, or deferred under exactly one matching generation;
- tensor reachable bytes are within their buffer and mutable layouts do not overlap;
- every recorded event is owned by one fence/upload/deferred record and no unrecorded event is polled;
- metadata/workspace/staging leases cannot return before their consumer fence acknowledgement;
- stream/event/view devices match; no poisoned/closing context accepts work;
- CUDA allocation/free counters do not change during warmed lease cycles;
- host synchronization counter remains zero in normal submission/poll paths; and
- closed context has zero live/deferred fences, leases, buffers, committed/reserved/leaked bytes.

Invariant failure is `Internal/kInvariantViolation`, poisons CUDA context when ownership might be
unsafe, emits a bounded snapshot, and stops work. It never repairs counters or makes a suspect slot
available.

## 17. Testing and benchmark requirements

All tests carry `m2` plus one category label. CPU tests run in every M0 preset; CUDA labels run on the
required GPU preset and never pass by skip in CI.

### 17.1 Unit tests (`platform-unit`)

- Every dtype name/size/classification and invalid enum.
- Shape rank 0/1/8/>8, zero extents, max dimensions, product/byte overflow, equality.
- Contiguous/padded/transposed/overlapping strides, reach calculation, zero-stride rule, permutation,
  slice boundaries/step/overflow, mutable-overlap rejection.
- Buffer move/release/zero bytes/subview bounds/alignment/host access/device rejection and allocator
  lifetime; CPU strided copy including overlap-safe contiguous path.
- Tracker reservation commit/rollback/limits/overflow/peak/leak and concurrent snapshot consistency.
- Pool full/FIFO-lowest-slot/move/double/stale/foreign release/generation retirement/destruction.
- Fake fence pending/complete/fail/abandon/deferred reclaim/stale/timeout/domain lifetime.
- On GPU: capability parsing, error mappings, nested guard restore, stream roles, unrecorded event,
  event record/query/ack, pointer attributes, and config cross-field validation.

### 17.2 Integration tests (`platform-integration`)

1. pinned H2D -> transfer event -> compute wait -> contiguous kernel -> D2H -> fence;
2. randomized strided input/output using metadata ring and workspace;
3. transfer stream disabled with identical output and explicit single-stream ordering;
4. ring/pool exhaustion followed by completion acknowledgement and deterministic reuse;
5. two contexts on different devices when available, proving guard/device isolation; and
6. shutdown with no work, completed-unacknowledged work, pending bounded-delay work, and retry after
   deadline.

Each asserts no output read before completion, exact final bytes, expected API-call/sync counters,
slot generations, tracker baseline, and healthy/closed state.

### 17.3 Correctness tests (`platform-correctness`)

Generate deterministic rank 0..8 shapes, legal contiguous/padded/permuted strides, dtype sizes, slice
offsets, and byte patterns. Compare CUDA output byte-for-byte with `CopyTensorCpu`; at least 10,000
cases nightly and 1,000 presubmit. Include empty/scalar/misaligned-rejected/boundary cases. Repeat with
different pool histories to prove addresses/generations do not affect results.

### 17.4 Stress tests (`platform-stress`)

- At least 100,000 event, buffer-pool, metadata-ring, staging, and workspace acquire/use/ack/release
  cycles across fixed seeds; validate after every operation.
- Saturate all pools, interleave out-of-order fence completion, abandon a bounded fraction, reclaim,
  and wrap small test generations.
- Nightly multi-hour copy/ring soak with bounded memory and periodic counter snapshots.
- CPU fake MPMC adapter under TSan; CUDA resource ownership remains one worker thread.

### 17.5 Failure tests (`platform-failure`)

- Invalid/missing device, unsupported SM/toolkit, impossible budgets, allocation/pinned exhaustion,
  and each injected create cleanup prefix.
- Invalid direction/range/alignment/pointer kind, pageable normal copy, wrong device/stream, launch
  rejection, event pool exhaustion, stale/duplicate acknowledgement, early lease release.
- Async illegal address/assert/timeout/device-lost classification in isolated subprocesses; subsequent
  submission rejected and worker exits.
- Observer/free/destroy failure accounting, poisoned shutdown, pending-work deadline, repeated close,
  and destruction-contract death tests.

Every failure asserts status/reason, health scope, no unrelated mutation, no premature reuse, and
exact final accounting (or explicit leaked bytes for an unrecoverable poisoned free).

### 17.6 Compute Sanitizer (`m2-compute-sanitizer`)

Run official tools as separate bounded CI invocations:

```text
memcheck: integration + randomized copy; leak check and stream-ordered race tracking where applicable
racecheck: test kernels (after memcheck is clean)
initcheck: kernel/global reads with initialized fixtures
synccheck: synchronization-bearing test kernels
```

Any reported InferX error/warning is failure; suppressions require toolkit-version-scoped rationale.
Store command, tool version, exit code, and log. The deliberate illegal-access child is an expected
failure fixture and is not mixed into the clean suite.

### 17.7 Performance benchmarks

Record, but do not compare across unlike machines:

- pageable versus pinned H2D/D2H and D2D bandwidth at 4 KiB..256 MiB;
- raw CUDA allocation/free versus warmed fixed-pool acquire/release;
- event acquire/record/query/ack and cross-stream wait overhead;
- direct CUDA versus wrapper copy/event submission; and
- direct versus wrapper no-op/byte-copy kernel launch.

Warm up, pin host thread/CPU governor where controlled, use CUDA events for device time and steady
clock for host submission, report p50/p90/p99 and at least 30 repetitions. JSON records GPU, SM,
driver/runtime/toolkit, compiler/NVCC, clocks/power mode when available, architecture flags, config,
sizes, and API counters.

At steady state, pool lease cycles make zero CUDA allocation/free calls and zero host heap allocations.
Wrapper host submission overhead must be <=3% median versus the operation-identical direct CUDA
microbenchmark; otherwise profile and accept an ADR/data-structure change before merge. Bandwidth and
absolute latencies are baselines, not universal gates.

## 20. Risks and required experiments

| Risk/question | Evidence | Decision/fallback |
|---|---|---|
| CUDA 13.0 host-language or runner mismatch | Compile/run matrix for accepted compiler, NVCC, SM | Isolate `.cu` at C++20; never lower host C++23; block M2 if no required runner |
| Tensor layout analysis rejects needed M3/M4 view | Artifact/operator fixture survey plus transpose/padded corpus | Extend explicit layout descriptor through ADR; do not add implicit unsafe stride behavior |
| Shared allocation-domain lifetime adds overhead/cycles | Ownership tests and allocation benchmark | Keep off lease hot path; replace with intrusive domain handle only if measured and lifetime-equivalent |
| Pageable call or raw free introduces host sync | API counters and submission microbenchmarks | Reject pageable normal path; allocate/free only startup/shutdown |
| Event query reports sticky prior error ambiguously | Subprocess fault matrix and first-poison capture | Poison device; never attribute uncertain async fault to one request |
| Pool/event generation wrap | Near-wrap fake tests | Retire slot; never wrap to a live-looking token |
| 3% wrapper gate is noisy | 30+ paired runs, affinity/governor, confidence interval | Optimize first; revise only with raw evidence ADR |
| Pinned budget harms host stability | escalating allocation test and system telemetry | Keep conservative explicit cap; fail startup rather than over-pin |
| Shutdown deadline expires with live GPU work | bounded-delay test | Retain context/resources and retry/exit worker; never free uncertain memory |

CUDA documentation explicitly permits asynchronous stream/event destruction but does not make early
buffer reuse safe; M2 therefore bases reuse on acknowledged completion fences. CUDA also permits
pageable “async” transfers to synchronize/stage, so production async copy requires pinned memory.

Primary NVIDIA references for these contracts:

- [CUDA stream management](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__STREAM.html)
  documents nonblocking stream creation/waits and asynchronous destruction behavior.
- [CUDA event management](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__EVENT.html)
  defines record/query/not-ready semantics and event reuse observations.
- [CUDA API synchronization behavior](https://docs.nvidia.com/cuda/cuda-runtime-api/api-sync-behavior.html)
  explains why pageable copies and ordinary allocation/free cannot be assumed host-asynchronous.
- [CUDA 13.0 runtime error types](https://docs.nvidia.com/cuda/archive/13.0.0/cuda-runtime-api/group__CUDART__TYPES.html)
  defines not-ready versus process-inconsistent illegal-address/timeout failures.
- [Compute Sanitizer](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/index.html) defines
  memcheck, racecheck, initcheck, and synccheck scope and limitations.

## 21. Definition of done and handoff

### Tensor/runtime

- [ ] Tensor/runtime targets are CPU-only, installed, self-contained, C++23, and consumer-tested.
- [ ] All dimension/stride/offset/byte/alignment calculations are checked; mutable overlap is rejected.
- [ ] Buffer/domain/view lifetimes and explicit release are enforced under sanitizers.
- [ ] Accounting and pool generations return exactly to baseline for every success/failure fixture.

### CUDA

- [ ] No generic header/source includes CUDA and CPU configure never discovers/loads it.
- [ ] Required GPU lane records accepted toolkit/driver/SM and has no skipped GPU tests.
- [ ] Normal copies/kernels are asynchronous, use nonblocking streams/events, and record zero host-sync
      calls and zero per-cycle allocations after warm-up.
- [ ] Fences, metadata, staging, and workspace remain owned until explicit acknowledgement.
- [ ] Sticky async faults poison the context; shutdown never releases memory with uncertain work.

### Verification/evidence

- [ ] Unit, integration, correctness, stress, failure, performance, and Compute Sanitizer suites meet
      their exact gates and are independently selectable.
- [ ] memcheck/racecheck/initcheck/synccheck are clean for the supported test path.
- [ ] Random CUDA strided copies match CPU byte-for-byte and all final counters/leases are zero.
- [ ] Wrapper overhead is <=3% or an accepted evidence-backed ADR changes implementation/gate.
- [ ] ADRs 0014-0020 and tensor/memory/CUDA docs match code; M0/M1 gates remain green.

The M2 handoff includes accepted ADRs, public tensor/runtime API docs, CUDA capability/evidence JSON,
pool geometry/accounting reports, sanitizer logs, correctness seeds, and benchmark JSON. M3 consumes
immutable mapped host tensor views without CUDA dependency. M4 consumes tensor views, workspace
leases, async copy, and completion fences for reference operators. M5/M6 may replace internal pool
geometry but cannot reuse addresses/resources before fence acknowledgement or expose CUDA types to
the control plane.
