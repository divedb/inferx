# M11 implementation specification: cross-request prefix caching

- Status: proposed implementation contract
- Roadmap milestone: M11 in [`docs/plan.md`](../plan.md)
- Prerequisites: completed [M10](m10.md) and [M6](m6.md), including M1-M9 transitively
- Immediate consumer: M12 single-GPU performance work
- Later consumers: M13 quantization/model expansion, M14 process/tensor parallelism, M17 speculative
  decoding, and M18 disaggregated prefill/decode

> **Re-planning note (2026-09-03, [ADR 0042](../adr/0042-retire-m1-simulator.md)):** the M1 CPU
> scheduler simulator this specification assumed as its offline oracle was removed. Simulator-based
> gates, tools, stages, and imported-workload plans below are void until re-planned against real
> execution (serving benchmarks, recorded traces, and soak suites).


This document turns M11 into an executable engineering plan. It defines a namespace-complete prefix
identity, a bounded page-radix index, exact-token collision guards, immutable shared full-page
ownership, lookup/pin/attach/insert/evict/reset transactions, physical-capacity and quota accounting,
tenant isolation, M8 scheduler integration, an optional cache-aware waiting policy, M10 telemetry and
failure containment, debug/control APIs, replay, tests, performance evidence, default selection, and
the handoff to M12.

M11 reuses committed KV across requests. It does not share partial pages, cache logits/hidden states,
change tokenization or model numerics, permit cross-namespace discovery, or let cache/index code bypass
the coordinator, M6 generations/pins, M8 two-phase scheduling, or M10 privacy and health rules.

## 1. Outcome

At the end of M11, InferX can:

1. derive one canonical namespace for every semantic input that can change KV values or sharing
   policy, including model/revision/weights, attention/RoPE/numeric/KV layout, adapter placeholder,
   tokenizer/template provenance, device-pool topology, and tenant namespace;
2. index full token pages in a fixed-capacity compressed radix/prefix structure and return the longest
   exact page-aligned prompt match while guarding every digest collision with token equality;
3. give a completed full KV block one cache owner, attach the same immutable block to multiple sequence
   tables, and distinguish cache ownership, table ownership, lookup pins, execution pins, quota, and
   physical residency exactly;
4. pin a match through M8 proposal/reservation, atomically attach it to a request table, and schedule
   only the unmatched prompt suffix without exposing stale handles or mutable shared tails;
5. insert newly completed full pages only after a successful final fence and matching completion,
   while treating duplicate/saturated insertion as an optional cache miss rather than request failure;
6. evict deterministic lowest-priority least-recently-used leaf pages only when no table owner, lookup
   pin, execution pin, pending transaction, or uncertain fence can reference them;
7. evict cache pages before M8 request preemption under pressure and preserve the physical guarantee
   for every admitted request when a previously evictable hit becomes protected;
8. isolate tenants/namespaces absolutely, reset one namespace or the full cache without invalidating
   active requests, and expose privacy-safe bounded debug snapshots;
9. use matched-token cost in ordinary scheduling while keeping the M8 reference waiting order, with a
   separate deterministic cache-aware policy behind configuration and replay; and
10. prove cache-on/off logits/tokens are equal, meet the 100-microsecond index and reuse-performance
    gates, and preserve M10 containment, observability, container, soak, and evidence contracts.

```text
tokenized prompt + immutable execution/tenant namespace
                         |
                         v
                read-only match preview
             longest exact full-page prefix
                         |
          scheduler estimates unmatched-token cost
                         |
                         v
            prepare generational lookup pins
          + quota/protection/eviction transaction
          + sequence-table shared-prefix attach
          + unmatched append/workspace/step plan
                         |
                 backend accepts plan
                         |
               no-fail ownership commit
                         |
          cached/computed counters start at match
                         |
          unmatched prompt/decode executes normally
                         |
         successful full fenced pages -> optional insert

pressure/reset -> deterministic leaf eviction/tombstone
             -> active table owners remain valid
             -> physical block free only after every owner/pin/fence is gone
```

M11 is complete only when no cross-namespace page can be observed or attached, every cache reference
is generation- and fence-safe, cache-disabled execution remains feature-equivalent, and cache-on/off
outputs are identical for every declared reuse percentage and page size.

### Implementation status (2026-08-31)

This file is a documentation specification only. This change does not authorize or add M11 source,
test, build, cache, admin, or benchmark implementation. The eventual implementation must extend M6's
block metadata/table transactions, M8's proposal/commit model, and M10's schemas rather than add an

## 2. Scope boundaries

### 2.1 In scope

- One prefix cache per loaded model/device KV pool, partitioned by complete cache namespace.
- Page sizes already supported by M6: 8, 16, and 32 tokens, one immutable size per pool.
- Full-page token/KV entries only; longest prompt match at page boundaries.
- Compressed radix edges over sequences of full-page labels with exact token-page collision guards.
- Fixed-capacity host node/edge/token metadata and use of M6's fixed device KV block pool.
- Multiple read-only sequence-table owners for one cached full page.
- Cache owner, table owners, lookup pins, execution pins, pending ownership, and generations.
- Transactional preview, match pin, protection capacity, table attach, insertion, eviction, and reset.
- Global and namespace cache budgets, deterministic prioritized LRU leaf eviction, low-water behavior.
- Same-namespace sharing for raw/chat/token-ID prompts whose exact normalized token pages match.
- M8 counters, cost/admission/chunk integration and optional deterministic cache-aware queue ordering.
- Embedded control/debug API and optional protected local admin adapter; no public untrusted cache API.
- M10 metrics/traces/logs/health/diagnostics/fault injection/replay/container/soak extensions.

### 2.2 Explicitly out of scope

- Partial-page sharing, copy-on-write tails, sharing a writable page, caching fewer than one full page,
  or attaching a page whose last write/fence is uncertain.
- Cached hidden states or logits. The initial request must still execute at least one prompt token to
  produce first-token logits.
- Cache lookup by text, decoded output, approximate token equality, semantic similarity, embeddings,
  or an unverified digest alone.
- Cross-tenant sharing, global deduplication that ignores tenant, timing-based cross-namespace probes,
  or tenant names in public metrics/logs/safe diagnostics.
- Persistent disk/remote KV cache, CPU/NVMe offload, cache replication, transfer between GPUs/processes,
  or disaggregated prefill; M14/M18 own later topology.
- Caching poisoned pages, failed/tentative writes, partial completion, mutable adapter state, unsupported
  position policies, or dynamic model state.
- Automatically changing M8 request priority, deadline, fairness, or preemption merely because a cache
  hit exists. Only the optional named cache-aware policy may change waiting order.
- Public HTTP cache contents, raw token debug output, arbitrary index mutation, or reset controlled by
  ordinary generation clients.
- Treating cache insertion failure as model-request failure when execution state is otherwise valid.

## 6. Prefix namespace and key

### 6.1 Namespace-complete identity

Every lookup begins at exactly one immutable `PrefixNamespace`. Its canonical serialized fields are:

| Field | Required identity |
|---|---|
| cache schema | prefix-key, page-label, index, and checksum versions |
| model | public model slot plus full validated semantic package/weights fingerprint and revision |
| model math | architecture/config digest, layer/head/head-dimension, attention mask/window policy |
| positions | RoPE base/scaling/type/factors, absolute-position policy, maximum context |
| numerics | weight/activation/KV dtype, M4 numeric policy, backend semantic variant |
| KV layout | pool ID/generation, page size, K/V layout/alignment schema, device/compute capability |
| adaptation | ordered adapter/tuning-set digest; explicit `none` in M11 |
| prompt provenance | tokenizer vocabulary/normalizer/pretokenizer/decoder and chat-template digest |
| topology | process/worker/device/rank/shard schema; single local rank in M11 |
| isolation | opaque strong `CacheNamespaceId` derived by trusted admission policy |

Sampling parameters, output limit, deadline, request priority, response mode, trace ID, request ID,
and arrival time are not KV semantics and do not fragment the key. Raw model path, tenant name,
credential, prompt text, or pointer is not serialized.

All fields are length-delimited, byte-order-defined, canonical, and checked. The namespace fingerprint
is domain-separated BLAKE3-256 over this serialization. Equality first compares the complete canonical
value; the digest is an accelerator, never the isolation authority. Unknown/missing required fields
fail namespace creation and readiness rather than defaulting to another scope.

### 6.2 Tenant namespace mapping

Embedded callers receive a trusted `CacheNamespaceId` through admission options. HTTP serving maps
M9's authenticated principal/admission result to a namespace using a fixed bounded policy. Raw bearer
credentials and user-provided `user` strings never select the namespace directly.

When authentication/tenant mapping is disabled, all requests use one explicitly named process-local
anonymous namespace and documentation warns that they intentionally share. Deployments needing
isolation must configure authentication and mapping. Namespace IDs are strong random/configured
values stored only in owner state; telemetry uses a per-process correlation hash at most.

No lookup traverses another namespace root, even to learn hit/miss counts. Per-namespace capacity and
reset authorization are resolved before index access. Deleting/recreating a tenant creates a new
namespace generation; old entries cannot become visible under a reused display name.

### 6.3 Page labels and prefix keys

The immutable tokenized logical history is partitioned into page-size token arrays from position zero.
Only complete pages receive labels. For logical page `i`, a `PageLabel` contains:

- page index and exact page-size token IDs in canonical little-endian representation;
- domain-separated digest over namespace fingerprint, page index, and exact page tokens; and
- cumulative prefix digest chaining the preceding cumulative digest and this page label.

A `PrefixKey` at a page boundary contains namespace fingerprint, page count/token count, cumulative
digest, and key schema version. It does not contain a physical block handle. The radix path plus exact
page tokens is the collision guard.

Digest equality without exact namespace and token-page equality is a collision event. The candidate
is not returned, touched, pinned, or attached. Injected collision tests force identical digests for
different pages/namespaces. Production collision increments a bounded critical cache event and
quarantines the affected index branch; any evidence of cross-namespace traversal is an isolation
invariant and follows M10 process-fatal containment.

Token digests and exact token arrays are sensitive. They remain in fixed host cache metadata only and
are excluded from ordinary metrics/logs/traces/safe diagnostics.

## 7. Match ceiling and logical semantics

M11 caches KV, not the hidden state/logits for the last prompt token. An admitted generation request
must execute at least one prompt token before sampling its first output.

For prompt length `N` and page size `P`, the greatest attachable prefix is:

```text
max_attach_tokens = Floor((N - 1) / P) * P, for N > 0
```

Therefore:

- prompts of one page or less have no attachable cross-request prefix;
- a prompt ending exactly on a page boundary leaves its final full page to recompute;
- a prompt with one or more tokens after a boundary may attach through the preceding full page; and
- lookup never returns a zero-work prompt requiring cached logits.

All token positions remain their original absolute positions. The first unmatched chunk reads the
attached shared prefix and appends only `[matched_tokens, chunk_end)`. M4/M5 attention and RoPE see the
same logical sequence as cache-off execution.

Full final prompt pages may still be inserted after successful computation because they are useful to
a future prompt that extends beyond them. Full pages containing committed decode-history tokens may
also be inserted under the configured insertion scope; a future multi-turn-style prompt matches them
only if its exact token history and complete namespace agree.

## 8. Bounded compressed page-radix index

### 8.1 Structure

There is one root per live namespace. A compressed edge stores a run of one or more `PageLabel`
records; each record has exact page tokens and an optional Ready `CachePageRecord`. Runs never cross a
namespace. Children are stored in deterministic order by page digest, then exact token IDs.

The index uses startup-sized fixed arenas for roots, nodes, edges, page-label/token storage, child
slots, eviction-heap entries, namespace records, lookup scratch, and transaction journals. Strong
node/edge generations prevent a stale cursor/lease from resolving reused metadata. There is no
serving-time metadata heap allocation.

Every full page position on an edge is a matchable prefix and can own one cached physical block.
Structural edge compression does not change logical page identity or eviction granularity.

### 8.2 Lookup

Given a namespace and prompt pages up to the match ceiling:

1. validate namespace/index generations and bounded scratch;
2. select the matching child by digest in deterministic order;
3. compare the entire exact page token array before accepting the label;
4. validate cache record state/checksum/physical handle generation;
5. continue until page mismatch, missing/non-Ready record, ceiling, or configured lookup cap; and
6. return a value-only `MatchPreview` containing matched count, ordered strong node/page/block handles,
   index generation/access-ordinal snapshot, and capacity/protection cost.

Preview neither pins nor updates LRU. It may become stale immediately and contains no pointers. A
zero-page miss is a valid result. Lookup performs work proportional to examined page tokens plus
bounded child search, not total indexed pages.

### 8.3 Insert, split, and merge

Insertion compares page-label runs and may:

- reuse an exact existing run;
- split an edge at the first differing page label or at a new prefix endpoint;
- create deterministic suffix edges/nodes from fixed transaction scratch; or
- find an existing page record and classify the candidate as duplicate.

Every allocation, child-order change, cache owner addition, checksum, and eviction-candidate update is
prepared before a no-fail commit. Capacity failure returns `not_inserted_capacity` and leaves request/
index/KV state unchanged.

After eviction/reset removes records, empty structural suffixes are removed. A non-boundary
structural node with one child may merge its adjacent compressed runs if fixed edge capacity permits;
required namespace roots, branch points, live page records, pinned cursors, and generation-visible
nodes are never merged away. Split/merge increments affected generations and is replayed exactly.

### 8.4 Invariants

- Every reachable page record is in exactly one namespace/path and its path depth equals page index.
- Exact page tokens and cumulative digest agree with the parent path.
- A Ready record has exactly one cache owner on one live Ready M6 block in the same pool/layout.
- One physical block appears in at most one cache record, though it may have multiple table owners.
- Children are canonically ordered and no two equal exact page labels exist under one parent.
- Every eviction candidate is a logical cached leaf and appears once in the correct priority heap.
- Arena live plus free plus retired slots equals capacity for every metadata class.
- Node/edge/block generations and entry checksums validate before mutation or returned match.

The invariant checker is allocation-free for bounded snapshots and has a deeper offline mode for
tests. A failed production invariant disables lookup/insertion immediately; ownership uncertainty
determines cache quarantine versus M10 KV/process poison.

## 9. Cache page record and integrity

A cache record contains:

- namespace/index/node/page strong identities and generations;
- prefix/page token counts and cumulative/page digests;
- exact M6 physical block handle and pool/layout/page-size identity;
- cache priority, insertion/access ordinals, hit/attach counters with checked saturation policy;
- cache owner state plus cached views of lookup-pin, table-owner, and execution-pin counts;
- entry state: Tentative, Ready, EvictPending, Quarantined, or Removed;
- insertion source: prompt prefill, recompute, or committed decode history;
- cache policy generation/reset epoch; and
- integrity checksum over all durable metadata fields.

The metadata checksum detects corruption/stale partial publication; it is not used as token identity
or claimed to prove arbitrary device-memory integrity. Optional test/debug device KV checksums/canaries
are capability-gated and measured separately. A checksum mismatch never returns a hit.

Tentative records are transaction-private and absent from public lookup/snapshot. Only Ready records
match. Quarantined records are unreachable for new lookup and retain physical ownership until the
manager proves safe release or process shutdown.

M6's allocator/owner registry is authoritative for physical references. Count fields in a cache
record are transactionally maintained mirrors used for bounded validation and snapshots; they never
authorize release by themselves. Commit checks the mirror against the allocator delta, periodic
reconciliation checks every reachable record, and any disagreement follows the ownership-invariant
failure path.

## 10. M6 shared-block ownership extension

### 10.1 Reference classes

M11 extends, without conflating, M6 references:

- **cache owner:** one persistent reference while a Ready cache record advertises the block;
- **table owner:** one reference for each active sequence table whose logical prefix reaches it;
- **lookup pin:** temporary cache lease preventing record eviction/restructure between validation and
  attach/rollback;
- **execution pin:** existing M6 ticket/fence reference preventing physical reclaim/mirror invalidation;
- **reservation owner:** existing pending allocation/transaction ownership; and
- **quota/protection charge:** capacity promise, never a physical reference.

All counts use checked fixed-width types. Underflow, overflow, double release, stale generation, owner
without a reachable table/record, or Free with any reference is an invariant failure. Snapshots report
each class separately.

### 10.2 Shared immutability

A block may acquire a cache owner only when:

- its entire page is valid at every layer/K/V location under M6's committed length;
- it is Ready after the matching final fence and completion identity;
- no append/tentative write or uncertain failure names it;
- page tokens, logical index, namespace, pool/layout, and table epoch validate; and
- the cache insertion/capacity transaction is prepared.

Once cache-owned or table-owned by more than one sequence, the block is immutable. No append may
target it. Sequence tables mark attached prefix entries SharedReadOnly. The first unmatched token
writes into a new exclusive page; there is no copy-on-write because only full pages are shared.

A block transitions to Free only after cache owner, all table owners, lookup pins, execution pins,
transactions, and fences are gone. Removing an index record drops only the cache owner; active table
owners continue reading the same generational block safely.

### 10.3 Sequence-table shape

An M11 table contains a contiguous zero-based shared read-only prefix followed by zero or more
exclusive entries. Shared entries cannot appear after an exclusive entry, contain holes, repeat a
handle, or exceed computed/cached counters. The existing exclusive partial tail remains the only
writable tail.

Table attach/detach/rebind increments `BlockTableEpoch` and produces a complete device-mirror update.
An accepted plan pins every shared read block exactly as it pins exclusive Ready pages. Device kernels
do not distinguish cached values mathematically; metadata only prevents writes and validates handles.

## 11. Match pin and attach transaction

### 11.1 Preview versus pinned lease

The scheduler may use a `MatchPreview` for cost/ranking, but it cannot attach or submit from it. During
M8 prepare, `BeginPinMatch` revalidates:

- namespace/index/reset generation and exact token pages;
- every node/record/checksum/block/pool generation and Ready state;
- match not beyond current prompt ceiling;
- no EvictPending/reset/quarantine state;
- lookup-pin capacity and checked count increments; and
- capacity-protection proof in section 14.

It returns one move-only `CacheLookupLease` owning the ordered lookup pins. Any change yields stale
preview/proposal rejection with no mutation; the coordinator retries from a fresh snapshot on a later
turn and does not busy-spin.

### 11.2 Composite attach prepare

Prepare atomically:

1. optional evictions needed to protect the match and future private quota;
2. lookup pins for every matched record/block;
3. adjusted request quota/protection charge;
4. new sequence table entries and table-owner increments for the shared prefix;
5. table/mirror epoch update and fixed metadata capacity;
6. M8 request counters/state (`cached_tokens`, source breakdown, `computed_tokens`);
7. unmatched prompt append/workspace/plan resources; and
8. trace/metric/access-ordinal updates.

The table remains publicly empty/old until the entire M8 plan is accepted. The composite validator
checks net free/evictable/protected/quota counts and every owner/pin delta. A match can be attached
without submitting an empty prompt step only if lifecycle admission has a separate no-fail attach
boundary; the initial implementation couples first attach to a valid unmatched prefill plan.

### 11.3 Commit and rollback

After backend acceptance, no-fail commit:

- applies selected cache evictions;
- adds table owners and publishes shared table/mirror entries;
- sets exact matched/computed counters;
- transfers lookup protection to table/execution ownership, then releases lookup pins;
- touches every attached page with one coordinator access ordinal;
- commits the unmatched append/ticket and lifecycle transition; and
- emits one canonical cache-attach/step event.

Before acceptance, rollback reverses tentative table entries/owners, protection/quota, lookup pins,
evictions, mirror staging, counters, plan resources, and access ordinals exactly. The normalized
request/index/allocator/table/quota snapshot must equal its pre-prepare value byte-for-byte.

Cancellation, deadline, policy update, reset, or shutdown racing after accepted attach follows M7-M10
event order. Active table owners remain safe even if the cache record is tombstoned concurrently by a
later coordinator turn.

## 12. Cache insertion transaction

### 12.1 Eligible candidates

After a matching successful completion, each newly full logical page in the committed contiguous
history may be considered when:

- insertion is enabled for its prompt/recompute/decode-history source;
- the request namespace/policy/reset generation remains current;
- the page block is Ready, fully valid, fenced, and has its sequence table owner;
- exact page tokens remain in immutable prompt/committed-output storage;
- no cache record already owns this physical block; and
- host metadata/cache-block/namespace budgets can be satisfied without violating low-water or future
  quota guarantees.

The completion/token/KV commit does not depend on cache insertion. If optional insertion cannot
prepare, request progress commits normally and a bounded skip reason is recorded.

### 12.2 Prepare and commit

Insertion prepares exact page labels/path split, fixed-arena records, entry checksum, cache owner,
priority/LRU candidate updates, and any evictions required by global/namespace budgets. It runs only
after the page's execution fence is known; the execution pin may remain until acknowledgement.

Commit publishes the Ready record and adds one cache owner atomically. It does not add another table
owner or change computed/output counters. The block becomes immutable before any later plan can write
it; because it is full, the current sequence's next append starts a new exclusive page.

If an exact prefix record already exists:

- validate its namespace/tokens/checksum/handle generation;
- classify as duplicate and optionally touch/promote only under the fixed policy;
- do not create a second cache record or cache owner; and
- leave the current request's private page/table unchanged.

Simultaneous same-prefix arrivals may therefore compute duplicate physical pages before the first
insert becomes visible. Exactly one wins canonical insertion; losers continue correctly and may
contribute later nonduplicate suffix pages. M11 does not require an unsafe post-compute table swap.

### 12.3 Failed and uncertain writes

A failed, cancelled, stale, partial, pre-fence, or uncertain page is never inserted. A transaction
prepared before a request/device failure rolls back metadata and cache owner. An asynchronous CUDA
fault follows M2/M10 poison and retains uncertain blocks; the index never advertises them.

## 13. Cache priority and deterministic LRU leaf eviction

### 13.1 Priority classes and access

The initial closed priority classes, low to high, are:

1. opportunistic committed decode-history pages;
2. ordinary prompt/recompute pages;
3. trusted configured reusable-prefix pages; and
4. reserved system policy pages, still evictable when no owner/pin remains.

Ordinary HTTP clients cannot choose/promote priority. Trusted embedded/admission policy may select a
bounded class. A duplicate insertion cannot promote unless the trusted policy authorizes it.

The coordinator assigns a checked monotonic access ordinal. A page is touched only when a match attach
commits, not on preview or failed prepare. Every page in the attached path receives the same new
ordinal in deterministic page order. Insertion sets its initial ordinal. Clock time is not LRU order.

### 13.2 Candidate eligibility

A physically reclaimable candidate must:

- be a Ready cache record at a logical cached leaf with no cached descendant;
- have exactly one cache owner, zero table owners, zero lookup/execution pins, no transaction/ticket/
  fence, and a matching live block generation;
- not be quarantined or already EvictPending;
- be permitted by namespace/reset/policy generation; and
- have valid metadata checksum/index invariants.

An entry with active table owners can be logically tombstoned for reset/metadata policy, but it cannot
count toward physical reclaim until those owners/pins drain.

### 13.3 Victim order and repeated leaf removal

Eligible leaves sort by:

1. cache priority ascending;
2. whether their namespace exceeds its soft block share (over-share first);
3. last committed access ordinal ascending;
4. insertion ordinal ascending;
5. namespace strong ID canonical order; and
6. node/page strong ID canonical order.

A fixed-capacity indexed min-heap maintains this tuple. Leaf/owner/pin/priority/access changes update
the exact heap entry transactionally. No stale heap entry may evict a reused generation.

Eviction selects the minimum, marks it EvictPending, removes its index record/cache owner, and releases
the block if all other refs are zero. Its parent may then become an eligible leaf and is inserted with
its preserved access/priority; repeat until reclaim target or victim bound. This leaf-only rule never
orphans a descendant or creates a prefix path with a missing earlier page.

Eviction events and replay contain ordinals/strong IDs/reasons but no token pages/namespace names.

## 14. Physical capacity, quota, and low-water accounting

### 14.1 Capacity categories

M11 publishes exact disjoint counts:

- Free physical blocks;
- exclusive active blocks;
- shared cache blocks with active table owners/pins (protected);
- cache-only eligible evictable blocks;
- cache-only blocks guaranteed reclaimable by repeated deterministic leaf removal;
- cache blocks temporarily pinned/tombstoned/quarantined/reclaim-pending;
- Reserved/Writing/Retired M6 blocks; and
- unallocated private-promise quota for admitted requests.

Cache residency is real physical use. A cached block is not “free” merely because it is evictable.

### 14.2 Per-request promise after match

Let final promised sequence blocks be `CeilDiv(prompt_tokens + max_output_tokens, P)` and attached
shared pages be `M`. The request still has table capacity for the full logical sequence, but its new
private-block promise is the checked difference between final promised blocks and `M`.

Attaching a cache block with no existing table owner converts it from evictable to protected and can
consume physical guarantee capacity even though no new block is allocated. The composite transaction
must maintain:

```text
free_blocks + guaranteed_reclaimable_cache_blocks
  >= total_unallocated_private_promise_blocks + resolved_low_water_reserve
```

after all staged evictions, attachments, insertions, quota changes, and appends. Shared blocks already
protected by another table owner do not consume another physical block, but logical/tenant request
limits remain charged per request.

This invariant prevents a later append from failing because a cache hit made pages non-evictable after
other requests had been promised their space.

`guaranteed_reclaimable_cache_blocks` is maintained from subtree protected-reference counts: it
includes cache-only pages that can become leaves after eligible descendants are removed, excludes a
page that is protected or lies on the retained path to a protected descendant, and includes
reclaimable sibling subtrees. The current eligible-leaf gauge is the immediately selectable subset.
Protection, insertion, eviction, pin, owner, split, merge, and reset transactions update both values
atomically. The capacity proof may conservatively count fewer pages, never more.

The per-turn victim bound limits coordinator work, not the truth of the promise. If reaching the
proved reclaimable total needs more leaf-removal turns, the request remains deferred with its prior
state unchanged; no allocation consumes that future capacity until the composite proposal can prove
and commit the required victims within its bounded transaction.

### 14.3 Cache budgets

Configuration bounds global cache blocks, host metadata bytes/nodes/tokens, namespace count, per-
namespace hard blocks/metadata, per-turn evictions, and maximum lookup pages. A namespace may have a
soft share for eviction priority but cannot exceed its hard limit. Unused namespace shares do not
create cross-namespace visibility.

Insertion is skipped or evicts eligible leaves to remain within budgets. A hit may require eviction of
other leaves to protect its matched blocks; if the proof cannot succeed, the cache proposal rolls back
and the request retries as a cache miss/reference path rather than breaking admission guarantees.

### 14.4 Pressure order

When M6/M8 reports low water or a valid proposal lacks guarantee capacity:

1. evict eligible cache leaves under section 13;
2. retry the proposal/capacity proof;
3. if insufficient, use M8 ready-request recompute preemption under its unchanged victim policy; and
4. if still impossible, defer/fail only under M8's temporary-versus-never-fits rules.

Cache eviction never preempts an in-flight request or removes active table ownership. M8 preemption of
a request with shared pages drops that table's owners as allowed; cache owners may keep the pages
resident, or pressure eviction may remove them afterward.

## 15. Scheduler counters and matched-token cost

M11 refines request progress accounting:

| Counter | M11 meaning |
|---|---|
| `prefix_match_preview_tokens` | unpinned advisory match for the current proposal only |
| `cross_request_cached_tokens` | attached page-aligned prefix from M11 records in this epoch |
| `same_request_retained_tokens` | M8 page-aligned prefix retained across preemption in this epoch |
| `cached_tokens` | usable epoch-start prefix, with each logical position counted once |
| `computed_tokens` | complete committed KV prefix, including cached and newly computed positions |
| `scheduled_tokens` | exact accepted outstanding range, unchanged from M8 |
| `committed_output_tokens` | committed sampled outputs, unchanged from M8/M9 |

At a fresh request attach, `cached_tokens == cross_request_cached_tokens == computed_tokens` and
same-request retention is zero. After preemption/requeue, source attribution is recomputed from pages
actually retained/attached; overlapping sources are not summed twice. `cached_tokens <= computed_tokens`
and M6 table length equals `computed_tokens` remain invariant.

The scheduler's prefill cost for token, workspace, estimator, and chunk selection is
`prompt_tokens - attached_cached_tokens`, subject to the one-token ceiling. Sequence/table/logical
limits still use the full prompt/context. A preview may estimate cost; only a pinned/committed attach
changes counters or resource charges.

Deadline feasibility uses the policy snapshot's cache-cost estimate and records preview versus final
match. If a stale preview loses its hit, the proposal rolls back and deadline feasibility is
re-evaluated; it cannot submit an underbudget plan or silently keep an impossible accepted estimate.

## 16. Waiting-queue policies

### 16.1 Reference policy

`cache.waiting_policy=reference` is the default. M8 effective priority, deadline, ready time, arrival,
and stable-ID ordering are unchanged. Cache matches change only the selected request's exact remaining
work/resource cost and plan fill. This is the cache-on/off fairness reference.

### 16.2 Optional cache-aware policy

`cache.waiting_policy=benefit_v1` is separately configured, fingerprinted, traced, and
benchmarked. It may reorder only requests that are tied on M8 effective priority and deadline class.
Within that cohort, the total order is:

1. pinned-independent preview matched tokens descending;
2. estimated unmatched prefill tokens ascending;
3. deadline ascending where present;
4. ready time and `ArrivalKey` ascending; and
5. strong request ID.

M8 aging remains first, so an older continuously eligible no-hit request eventually outranks fresh
hit requests. A configured maximum cache-aware bypass count provides an additional explicit bound:
after that many accepted later-cohort bypasses, the oldest eligible request is forced when its valid
minimum chunk fits. Failed proposals do not consume the bypass count.

Preview staleness at prepare rejects/retries the proposal. The policy never pins every waiting request,
touches LRU on speculation, crosses priority/deadline classes, or bypasses response/KV capacity.

Reference versus benefit policy comparison runs on identical recorded workloads (re-planned off the
removed CPU simulator; ADR 0042). Cache-aware remains off unless SLO-goodput/fairness evidence
justifies it independently of basic cache enablement.

## 17. Tenant isolation and side-channel boundaries

- A request can reference only the root selected by trusted admission and carried in its immutable
  request/cache namespace.
- Namespace comparison occurs before token digest/path lookup; a digest collision never causes a
  cross-root search.
- Physical blocks may have table owners only from the cache record's exact namespace. Owner add
  validates request namespace, not only handle.
- Namespace reset/budget/snapshot/control requires an authorization capability stronger than an
  opaque display ID.
- Public metrics aggregate cache behavior across bounded model slots and never label tenant,
  namespace, digest, prompt, or request.
- Logs/traces/safe diagnostics expose only fixed reason classes and optional per-process HMAC
  correlation; cache contents/token digests are sensitive.
- Timing can reveal hit behavior within the same namespace by design. Cross-tenant roots and metrics
  prevent direct cross-namespace cache probes; stronger hardware timing isolation is out of M11 scope
  and documented.

The isolation suite constructs identical token prompts under different tenant, model revision,
weights, RoPE, position policy, adapter placeholder, tokenizer/template, KV dtype/layout/page size,
device pool, and rank fields. Every pair must miss and must never share a physical handle.

## 18. Reset, drain, model reload, and control APIs

### 18.1 Control surface

The embedded administrative API exposes bounded asynchronous operations:

- get aggregate cache snapshot;
- list namespace summaries with opaque authorized cursor and fixed page size;
- request reset of one authorized namespace or all namespaces;
- wait/poll reset generation and reclaimed/deferred counts; and
- validate invariants or request a safe M10 diagnostic snapshot.

An optional server adapter is disabled by default and may bind only to the protected local admin
listener with M10 authorization. It is not part of the OpenAI compatibility profile. Sensitive token/
key inspection requires the separate build/runtime fixture-only gate.

### 18.2 Reset transaction

Reset is an ordered coordinator command:

1. increment the selected cache reset epoch and stop new preview/pin/insert in that scope;
2. invalidate outstanding uncommitted previews by generation;
3. mark matching records EvictPending/tombstoned in deterministic leaf order;
4. immediately remove/cache-release eligible unowned pages;
5. prevent old-policy completions from inserting after reset;
6. retain active table owners and lookup/execution pins until normal release/rollback/acknowledgement;
7. remove deferred records/cache owners when their last pins/owners permit; and
8. publish completion only when the requested logical scope is unreachable for new lookup, with
   separate immediate/deferred physical-reclaim counts.

The reset walker uses a generation-checked fixed cursor and processes at most the configured node/
eviction budget per coordinator turn. It yields between turns, exposes progress, and declares its
expected watchdog deadline; resetting 100,000 pages cannot monopolize the coordinator. New lookup in
the resetting scope stays disabled across the multi-turn operation.

Reset does not cancel requests, rewrite active table entries, clear M6 allocator counters, synchronize
the device, or claim all physical bytes reclaimed while active owners remain. A concurrent cancellation
or shutdown follows coordinator event order and is replayable.

### 18.3 Model reload and shutdown

M11 has no hot reload. During model/process shutdown, stop lookup/insertion, reset/tombstone cache,
drain lookup/execution pins and active table owners, release cache owners, require index/heap/arena
baseline, then continue M6/M10 teardown. If device ownership is uncertain, retain cache blocks with
the M6 arena and follow poison/forced-exit policy.

A future new model generation has a different pool/namespace and cannot see old records. Reusing a
public model name does not reuse its cache.

## 19. Cache events, replay, and safe debugging

Every mutation emits a bounded canonical event where M10 recording is enabled:

- namespace created/retired/reset begun/reset completed;
- lookup preview/miss/stale/pinned/attach committed/rolled back;
- radix edge/node allocate/split/merge/retire;
- insert prepared/committed/skipped/duplicate/rolled back;
- cache/table/lookup/execution owner or pin delta;
- touch/priority/leaf eligibility update;
- eviction selected/deferred/committed and physical release/reclaim-pending;
- checksum/collision/stale generation/quarantine/invariant/poison; and
- capacity/low-water/preemption interaction snapshot.

Events contain schema/event ordinal, hashed namespace correlation, strong generational IDs, page/token
counts, priority/access ordinals, old/new states/counts, resource deltas, policy/reset generation, and
stable reason. Structural traces omit exact token pages/digests. Fixture-sensitive replay may include
them only under M10 capsule policy.

`inferx-cache-replay` composes the production CPU index/transaction manager with the M6/M8 fake
allocator/scheduler and M10 structural trace. It must reproduce matches, stale previews, splits/
merges, owners/pins, victims, capacity, reset, counters, and invariants byte-identically. Structural
replay can use recorded page-label surrogates; collision/exact-token tests use protected committed
fixtures.

Safe debug snapshots report aggregate namespace counts/budgets, tree depth/edge/run distributions,
cache block states, owner/pin distributions, priority/LRU age buckets, hit/attach/evict/reset counts,
capacity proof, checksum/invariant status, and bounded strong-ID hashes. They never dump tokens, raw
digests, prompts, outputs, tenant names, KV contents, or physical addresses.

The cache owner publishes this information into the immutable bounded M10 status/diagnostic snapshot.
Admin, telemetry, watchdog, and diagnostic workers read only that publication; they never traverse
the mutable radix tree, eviction heap, allocator, or live owner tables.

### 20.1 Fixed metrics

Add fixed-cardinality series:

| Metric | Kind and bounded labels |
|---|---|
| `inferx_prefix_cache_lookups_total` | counter: miss, preview_hit, attach_hit, stale, rejected reason |
| `inferx_prefix_cache_tokens_total` | counter: matched, attached, saved-prefill, inserted, recomputed |
| `inferx_prefix_cache_blocks` | gauge: cached, protected, evictable, pinned, tombstoned, quarantined |
| `inferx_prefix_cache_operations_seconds` | histogram: lookup, pin, attach, insert, split, merge, evict, reset |
| `inferx_prefix_cache_evictions_total` | counter: pressure, budget, reset, namespace-retire, failure |
| `inferx_prefix_cache_insertions_total` | counter: committed, duplicate, capacity-skip, policy-skip, failure |
| `inferx_prefix_cache_resets_total` | counter: scope class and complete/partial/deferred/failure |
| `inferx_prefix_cache_integrity_total` | counter: collision, checksum, stale, invariant, quarantine, poison |

No namespace/tenant/prefix/token/request/digest is a label. Hit-token rate, physical reuse, saved work,
and amplification are derived from counters with documented denominators.

### 20.2 Health and containment

- Ordinary miss, stale preview, capacity skip, duplicate insertion, eligible eviction, or reset is
  healthy behavior.
- Host index capacity exhaustion skips insert or causes a cache miss; it does not fail valid inference.
- One bad entry checksum detected before attach is quarantined and makes cache health Degraded while
  other provably independent entries may continue only if the ADR validates isolation.
- A namespace mismatch, owner/refcount corruption, wrong physical generation, shared-page write,
  cross-root handle, or uncertainty about which table/kernel referenced a page poisons the KV/cache
  component and follows M10 unready/process containment.
- Cache disabled/quarantined falls back only before attach/plan acceptance. It never swaps a submitted
  request silently to a different ownership plan.

Cache coordinator progress joins M10 watchdog/health snapshots. Cache operation bounds are included in
coordinator turn deadlines; telemetry or debug capture cannot traverse the live tree.

### 20.3 Fault sites

Register fault injection before/after namespace creation, page hash/exact compare, node/edge/heap arena
reserve, split/merge, lookup pin, cache/table owner increment, capacity proof, mirror attach, insertion,
checksum validation, victim selection, cache-owner release, reset tombstone/deferred release, and
replay event. Collision/stale/checksum/overflow/underflow actions use disposable deterministic tests.

Startup proves with checked arithmetic:

- namespace/root/node/edge/page-token/heap/cursor/transaction/event capacities fit host budget;
- global and per-namespace block budgets plus M6 low-water reserve leave a viable active workload;
- maximum table-owner and pin counts cover active sequences/in-flight plans without overflow;
- match/attach/insert/evict/reset scratch covers configured pages/victims atomically;
- M6 block/table/mirror schemas support shared read-only prefixes for every page size/backend;
- M8 scheduler/counter/replay and M10 metric/fault/diagnostic schema versions are compatible;
- trusted namespace mapping cannot exceed namespace/controller capacities; and
- enabling cache-aware policy without cache or bypass bound is rejected.

Configuration does not silently shrink cache or active request limits. Resolved values and cache/
namespace/index/policy/system fingerprints appear in redacted startup evidence.

## 22. Failure behavior

| Failure | Required result |
|---|---|
| invalid/incomplete namespace | request/model capability failure before lookup; no fallback namespace |
| digest collision with unequal tokens | miss/quarantine branch, collision event; never attach/touch |
| host index/metadata/cache budget full | skip insert or deterministic eligible eviction; request continues |
| stale preview/node/block/reset generation | rollback proposal, release pins, fresh retry/reference miss |
| lookup-pin or owner-count overflow | no mutation; invariant containment, never saturating live-looking ref |
| attach/quota/mirror/plan prepare rejection | reverse composite rollback to exact snapshot |
| backend rejection after cache prepare | no visible attach/eviction/counter/LRU change |
| execution failure after accepted shared read | shared pages unchanged; drain execution pins, request failure rules |
| failed/partial/uncertain page write | never insert; rollback tentative cache metadata; poison if uncertain |
| duplicate simultaneous insertion | one canonical record; loser keeps private page and continues |
| no eligible eviction victim | rollback pressure proposal, defer or M8 preempt; no busy spin |
| metadata checksum corruption before hit | quarantine/no attach; degrade or poison by ownership certainty |
| stale physical generation or shared-page write | reject mutation, KV/cache poison, unready and controlled exit |
| reset with preview/pins/active tables | invalidate previews, tombstone/defer; active tables remain valid |
| cancellation/deadline during attach/insertion | coordinator event order; accepted ownership drains exactly once |
| cache disabled/quarantined | reference scheduling/execution before attach only; same API/token semantics |
| shutdown/device poison | stop lookup/insert, release only safe owners/pins, retain uncertain pool |

Every path has a stable M10 event/metric/health category. Cache optimization failure is not mislabeled
model failure unless ownership or isolation integrity is uncertain.

### 23.4 Integration tests

- Shared system prompts across concurrent raw/chat/token requests within one namespace.
- Multi-turn-style exact token prefixes including configured committed decode-history insertion.
- Simultaneous identical arrivals before/after first insert, duplicate resolution, and suffix caching.
- Requests join/leave shared pages while M8 chunking, mixed/alternating phases, low water, eviction,
  preemption/recompute, cancellation, deadline, slow client, and shutdown occur.
- Cache reset/quarantine during ready/in-flight/draining work; old tables remain valid and new requests
  miss.
- M9 HTTP auth-principal mapping to namespace and protected local control behavior.

### 23.5 Correctness and isolation

For every supported page size/backend/numeric policy, construct realized attach ratios at or nearest
page-aligned 0%, 25%, 50%, 75%, and 90%, always respecting the one-token match ceiling. Compare:

- cache off, cache on miss, cache on hit, post-eviction recompute, post-reset, and preempted execution;
- every committed KV page against the M6 contiguous/paged oracle within existing numeric thresholds;
- final hidden/logits at every first-unmatched/chunk/decode boundary;
- fixed-seed sampled token IDs, logprobs, stop/usage/text, finish reason, and HTTP/SSE output exactly;
  and
- scheduler/resource/counter terminal invariants.

Token outputs must be identical. Different model/revision/RoPE/position/adapter/tokenizer/template/
tenant/KV layout/page/device/rank namespace pairs produce zero matches and share zero block handles.

### 23.6 Stress, property, failure, and sanitizers

- Millions of randomized index insert/match/split/merge/touch/evict/reset operations with invariant
  check after each operation and minimized replay seed.
- At least 100,000 indexed pages across maximum namespaces with high-churn Zipf/uniform/adversarial
  prefixes, collision injection, arena pressure, and repeated generation reuse.
- Thousands of concurrent request lifecycle events through the real coordinator under near-full KV,
  low water, cancellation/deadline storms, resets, and telemetry/exporter outage.
- Fault injection at every section 20.3 site, including OOM during pin/reservation, failed page write,
  stale generation, corrupted checksum, no victim, mirror rejection, and device poison.
- ASan/UBSan for index/replay/control, TSan for engine/admin/snapshot interactions, Compute Sanitizer for
  shared-page reads/write rejection, and 24-hour M10 candidate-image soak with cache on/off phases.

At final quiescence all namespace/index/heap/owner/pin/quota/table/page/mirror/request/telemetry/control
counters return to baseline; quarantined/retired/poison-retained resources are explicit rather than
hidden.

## 24. Performance methodology and gates

### 24.1 Index operations

On the declared reference CPU with 100,000 indexed pages and representative namespace/prefix depth/
branch distributions, measure lookup miss/hit by depth, pin/attach prepare, insert/split/merge, touch,
one/multi-page eviction, reset enqueue, invariant sampling, host bytes, cache misses, and coordinator
turn contribution.

Use warmed fixed arenas, pinned CPU affinity/governor, randomized operation order with fixed seeds,
p50/p95/p99/max and confidence. The required p99 for prefix operations is <=100 microseconds. The
report lists operation mix and excludes neither exact token comparison nor checksum/capacity proof.
If the gate misses, a benchmark-backed ADR may change the index/design; the target is not silently
redefined.

### 24.2 End-to-end reuse

The M10 developer-preview workload gains a fixed prefix-reuse variant with at least 75% realized
reusable prompt tokens after the one-token ceiling. Compare cache off, cache on/reference order,
cache-aware policy, and warm/cold/reset/churn states using identical model/system/request seeds and
successful request set.

Measure TTFT, TPOT, end-to-end, output/SLO goodput, prefill/saved/recompute tokens, hit/attach rates,
GPU utilization, scheduler cost, physical/host cache memory, eviction/preemption, per-namespace share,
and token/outcome equality.

The selected cache configuration must:

- improve TTFT by at least 30% at >=75% reusable prompt tokens;
- regress no-reuse throughput by no more than 3%;
- meet the index, isolation, correctness, fairness, telemetry-overhead, memory, and soak gates; and
- show no cross-namespace reuse or unexplained capacity failure.

If the gates are not met, runtime `cache.enabled` remains false by default and the feature is reported
experimental pending redesign. Cache-aware ordering has its own evidence/default and cannot be enabled
merely because basic caching passes.

## 29. Definition of done

### Namespace, index, and ownership

- [ ] Prefix namespace contains every declared KV/isolation semantic and every differing field produces
      a miss with zero shared physical handles.
- [ ] Page digests are always exact-token guarded; forced collisions never attach/touch another entry.
- [ ] Radix match/split/merge, fixed arenas, generations, checksums, leaf heap, replay, and invariants
      remain deterministic under million-operation stress.
- [ ] Only full Ready fenced pages become cache-owned; shared blocks are immutable and all cache/table/
      lookup/execution/reservation/quota refs reconcile exactly.
- [ ] Pinned match, protection quota, table/mirror attach, counters, append, commit, and rollback are one
      valid M8 composite transaction with byte-equivalent rollback.

### Isolation, lifecycle, and scheduling

- [ ] Tenant/model/revision/RoPE/adapter/tokenizer/template/KV layout/page/device/rank isolation suite
      has zero cross-namespace hit or physical reuse.
- [ ] Insert/duplicate/evict/preempt/cancel/deadline/reset/quarantine/shutdown never expose failed,
      partial, stale, pinned, active, or uncertain pages.
- [ ] Cache pressure evicts only deterministic eligible leaves before M8 request preemption and never
      breaks admitted private-capacity guarantees.
- [ ] Cache reset makes scope unreachable to new lookups while active tables remain valid until normal
      owner/pin release; deferred physical reclaim is reported honestly.
- [ ] Reference waiting policy preserves M8 order; optional cache-aware policy is deterministic,
      bounded against starvation, and independently gated.

### Correctness, operations, and evidence

- [ ] Cache off/on at 0/25/50/75/90% realized reuse produces identical tokens/logprobs/text/usage/
      finish reasons and accepted KV/logit equality for every supported page/backend.
- [ ] M10 metrics/traces/logs/diagnostics/fault sites are fixed-cardinality/privacy-safe; telemetry
      on/off cannot change cache/scheduler/output decisions.
- [ ] Prefix operations meet <=100 microseconds p99 at 100,000 pages, or an accepted evidence-backed
      ADR changes the design/target before release.
- [ ] At >=75% reusable tokens, TTFT improves >=30% and no-reuse throughput regresses <=3%; otherwise
      cache remains off by default with limitations/evidence published.
- [ ] Stress, isolation, ASan/UBSan/TSan/Compute Sanitizer, container checks, 24-hour soak, resource
      reconciliation, ADRs 0073-0080, docs, fixtures, and evidence all pass without hidden skips.

## 30. Handoff to M12

M11 hands M12 a correctness-gated cache-enabled single-GPU baseline with complete namespace identity,
immutable shared paged KV, exact owner/pin/quota accounting, deterministic index/eviction/reset,
matched-cost scheduling, cache telemetry/fault/replay, and cache-on/off performance/correctness evidence.

M12 may add GPU sampling, asynchronous output processing, plan/GPU overlap, stable graph arenas, graph
caches, autotune, and profile-guided kernels. It must include cache namespace/page/table generations in
graph and metadata identities, pin shared pages through every overlapped/graph ticket, never capture a
writable alias to shared cache pages, preserve the one-token first-logits rule and cache-on/off output
equality, extend M10/M11 fixed schemas without tenant/prefix labels, and rerun no-reuse/reuse/24-hour
evidence against the M11 baseline.
